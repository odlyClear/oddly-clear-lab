# Planning the next production weeks

Owner-requested cadence: **two English science videos per day, fourteen per week**. The full production workspace has the fourteen week-one cards. Only the water full film and interactive page are complete. Week two and later have a defined method, not approved topic slates or finished media. No YouTube release schedule or background production automation is configured.

## Weekly loop

1. Read the previous slate, completed delivery reports, unresolved issues and actual finished reserve. Keep planned, rendered, reviewed, published and measured counts separate. Complete existing commitments before opening another fourteen-film batch unless the owner changes priority.
2. Review actual channel results at comparable ages where available: initially 24 hours and seven days after a real upload. Retain observation time, upload age, metric definitions and source. Unknown/missing values are not zero. If no uploads exist, select on mechanism clarity, visual feasibility, source quality and owner direction; do not invent analytics.
3. Collect more candidate questions than needed. Screen central claims and needed diagrams. Prefer useful follow-ups and adjacent questions while retaining room for distinct visual ideas. Competitor data can suggest questions but cannot validate the science or predict views.
4. Copy [the weekly template](../templates/weekly-plan.md). Assign unique `W02-01`…`W02-14` IDs for week two, then the corresponding week numbers. Select fourteen entries, two per day; give each a meaningful slug, duration, complete [episode brief](../templates/episode-brief.md), source boundaries and next action.
5. Group production by useful shared assets, then arrange varied daily topic pairs. Build a four-video finished reserve before the proposed launch. A two-per-day target is not proven capacity; record measured work and adjust the plan when needed rather than shipping a known defect.
6. Produce every episode using [the production method](production-method.md): research → script → voice/timing → graphics → render → QA → authorized release → observation. Follow each topic's causal mechanism rather than repeating water artwork indiscriminately.
7. During the week, record repeated viewer questions and obvious comprehension defects when real feedback exists. One low-exposure upload is weak evidence. Test a specific opening/presentation hypothesis where practical and keep track of other differences.
8. Close with actual finished/published counts, available comparable-age results, production time/revisions/costs with evidence, bottlenecks, next candidates and a concrete handoff. Reuse the same loop every later week.

Dates and posting times remain proposals until a launch/publication task assigns them. The original first-week proposal uses 15:00 and 21:00 Europe/Berlin; these are test slots, not proven optimal times or existing scheduled uploads. Do not create automations or uploads just because this planning document describes a cadence.

The complete operational plan, episode cards and tool-adaptation details are in the owner's production workspace. This checkout's build commands create webpages, not fourteen videos. If a task requires unavailable source materials, identify exactly what is missing while continuing any independent work that is within scope.
